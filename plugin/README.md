# davinci-laya-decisions

Плагин ZCode: локальный **decision-engine Laya** (`127.0.0.1:8095`) в точках контроля
агентного цикла. Laya не пишет код и не заменяет основную модель — она быстро
(десятки миллисекунд, локально, без сети и без API-ключей) отвечает на
типизированные вопросы `choice` / `score` / `noul` о коротком тексте, а плагин
использует эти ответы там, где решение дешевле вычислить, чем рассуждать.

Реализация — по ТЗ `<repo>\engine\DaVinci_ZCode_Laya_Integration_TZ.md` (v1.0).
Движок Laya дополнен для нужд интеграции (см. `docs/ENGINE-API.md`).

## Что делает плагин

| Компонент | Событие ZCode | Поведение по умолчанию |
|---|---|---|
| **RiskGate** | `PreToolUse` (Bash/Write/Edit/MultiEdit) | `shadow`: считает риск (правила + Laya), пишет в локальные метрики, **не меняет разрешения**. В режиме `ask` спрашивает только в Autonomous mode (`guarded`); в Full access (`yolo`) — молчит |
| **EvidenceLedger** | `PostToolUse`, `PostToolUseFailure` | тихо ведёт факты в любом режиме, включая yolo: изменённые файлы, запущенные проверки и их коды, неразрешённые ошибки; проверки из `laya_run_check` подмешиваются по файлу проекта |
| **DoneGate** | `Stop` | считает конкретные пробелы по типу изменений и доступным проверкам; по умолчанию — одно короткое уведомление (без `decision:"block"`) только при доступной незапущенной/упавшей проверке. Уведомление доставляется агенту через `continue:true` один раз на сессию; `block` — только в явно разрешённом режиме |

`failing-tests` остаётся `high` и после исчерпания уведомления/блокировок; меняется только действие (`log` вместо `notify/block`), пробел не исчезает.

| **TaskRouter** | `UserPromptSubmit` | `log`: классифицирует задачу (fast/balanced/deep) **только в метрики**; `advise` — opt-in для замеров, не для каждого промпта. **Модель не переключает** |
| **ContextSelector** | MCP-инструменты | self-fetching поиск/чтение/проверки, ранжирование, триаж — с сохранением источника в `laya_get_chunk` |

Плюс **13 MCP-инструментов**: 10 прежних (`laya_health`, `laya_decide`,
`laya_classify`, `laya_score`, `laya_batch`, `laya_search_relevant`,
`laya_log_triage`, `laya_context_pick`, `laya_get_chunk`, `laya_rank_diff`) и
новые `laya_search`, `laya_read_relevant`, `laya_run_check`.

## Как этим пользоваться в чате

**Три способа, по возрастанию «ручности»:**

1. **Автоматически** — вообще ничего не делаете:
   - гейты риска, ledger и контроль завершения работают сами (это хуки, их не нужно вызывать);
   - навык `laya-decision-workflow` модель подхватывает сама, когда видит большой вывод/поиск;
   - health проверяется на старте сессии и при диагностике, а не на каждом ходе.

2. **Словами** — самая надёжная форма, модель вызовет инструмент:
   - «найди в проекте X через `laya_search` и покажи только выдержки»;
   - «прочитай релевантные блоки файла через `laya_read_relevant`»;
   - «запусти `laya_run_check` и покажи exit code»;
   - «разбери этот лог через `laya_log_triage`».

3. **Командой** — если хотите жёстко зафиксировать поведение:

| Команда | Что делает |
|---|---|
| `/laya-triage <файл или команда>` | триаж лога: уникальные ошибки с `file:line`, без чтения целиком |
| `/laya-search <запрос>` | поиск + ранжирование: порядок, сниппеты, подсказки чтения |
| `/laya-review` | ранжирование текущего `git diff` (приоритеты для просмотра) |
| `/laya-status` | доступность Laya, чекпоинт, режимы, метрики |
| `/laya-all [on\|off]` | **режим экономии контекста**: self-fetching инструменты + `router=log`; разрешения и `activeModes` не меняются; обязательного `laya_*` на ход нет |
| `/laya-mode <risk\|done\|router> <режим>` | точечное переключение режимов гейтов |
| `/laya-bench` | замер латентности перед включением активных режимов |

**Когда НЕ использовать отбор:** если файл/вывод помещается в одно чтение
(замеренный ориентир: ~700 строк / ~36 КБ) — читайте напрямую, отбор добавит
лишний round-trip, который нечем оплатить.
Правило простое: **большие логи, широкие поиски (сотни попаданий) — через
плагин; мелкое и точное — обычным чтением.** Несколько решений — один вызов
`laya_decide`/`laya_batch` (один round-trip вместо N).

**Одноразовая настройка (после включения плагина):**

1. Начать **новую сессию** ZCode — команды, инструменты MCP и хуки подхватываются
   при старте сессии (в давно открытой сессии их не будет).
2. При первом вызове MCP-инструмента ZCode спросит разрешение — разрешите
   (можно выбрать «разрешать всегда», чтобы не отвлекало).
3. Проверить: `/laya-status` — должны быть видны чекпоинт, режимы и метрики;
   `/laya-triage` в списке команд.

## Три принципа, на которых всё держится

1. **Вероятность ≠ доказательство.** Laya выдаёт оценку, детерминированные правила
   и факты (`git status`, коды возврата тестов) имеют приоритет. Низкий риск от
   Laya **никогда** не расширяет разрешения; на выходе гейта вообще нет `allow`
   — только «ничего не делать» или «спросить».
2. **Fail-open.** Laya недоступна, таймаут, битая схема ответа — ZCode продолжает
   работу штатно. Гейты не делают авторазрешений и не выдумывают вердикт.
3. **Измерять, а не обещать.** Все решения пишутся в локальные метрики
   (латентность, сбои, действия, доля обрезки состояния). Активные режимы
   (`ask`/`block`/`advise`) включаются только после просмотра этих чисел.

## Laya Work (`/work`)

Плагин отправляет события решений в локальную панель движка:
`http://127.0.0.1:8095/work`. Быстрый путь — spool-файл в
`<engine>/data/work-spool`; hook не ждёт сеть и не замедляется, если панель
недоступна. В конфиге `work.spoolDir`/`work.tokenFile` задают обмен с движком.
Панель показывает вход, фактический ответ Laya, действие плагина, тайминги,
evidence, сокращение выдачи и ручную разметку по `call_id/question_id`.
Подробности — `docs/WORK.md` в репозитории стека.

## Установка

Плагин лежит в каталоге `plugin/` этого репозитория. Корневой
`marketplace.json` указывает на него, поэтому репозиторий можно добавить как
локальный маркетплейс.

1. Открой **Settings → Plugin Management → Add marketplace** и выбери корень
   репозитория (каталог с `marketplace.json`).
2. Включи плагин **DaVinci × Laya: локальные решения**.
3. Начни **новую** сессию ZCode: MCP-инструменты и хуки загружаются при старте
   сессии.
4. Проверь: `/laya-status` в чате ZCode или
   `node plugin/scripts/laya-admin.mjs doctor`.

**Требования:** Node.js ≥ 20, запущенный `laya-server` (порт 8095,
`engine\start-laya.cmd`). Плагин работает и без сервера — в пассивном режиме.

| Команда | Что делает |
|---|---|
| `/laya-status` | доступность, чекпоинт, режимы гейтов, метрики (сбои, p50/p95, обрезка) |

## Конфигурация

`config.json` в каталоге данных плагина (`%ZCODE_PLUGIN_DATA%`, при отсутствии —
`~/.zcode/davinci-laya-decisions/`). Создаётся автоматически при первом запуске.
Менять можно вручную или через `/laya-mode`.

```json
{
  "layaUrl": "http://127.0.0.1:8095",
  "timeoutMs": 1500,
  "riskGate": { "mode": "shadow", "activeModes": ["guarded"], "askMinConfidence": 0.7, "stateCharBudget": 20000 },
  "doneGate": { "mode": "report", "activeModes": ["guarded"], "maxBlocksPerSession": 1, "notify": true },
  "router": { "mode": "log" },
  "sessionContext": false,
  "budget": { "maxLen": 1024, "hardStateChars": 20000, "marginTokens": 12 },
  "runChecks": { "autoDiscover": true, "commands": {}, "timeoutMs": 180000 },
  "search": { "maxHits": 200, "contextLines": 2, "timeoutMs": 15000 },
  "readRelevant": { "maxBytes": 2097152, "budget": 8000, "contextLines": 6, "maxBlocks": 8 }
}
```

`stateCharBudget` — только жёсткий предохранитель. Реальный бюджет считает
`/count` по полной постановке вопроса: `max_len` — вся последовательность,
`head_max_len` — инструкция + варианты. Если state не помещается, он
сокращается с маркером; если не помещается вопрос — `/decide` не вызывается.

`activeModes` ограничивает вмешательство гейтов режимами разрешений ZCode:
`guarded` — это «Autonomous mode», а `yolo` («Full access»), `build`, `edit`,
`plan` получают только запись в метрики. В Full access пользователь согласился
один раз — Laya ничего не переспрашивает и не блокирует. Пустой массив снимает
фильтр и возвращает прежнее поведение во всех режимах.

Каталог данных:
```
config.json                     настройки (правит пользователь)
state/ledger-<session>.json     факты по сессии (файлы, проверки, ошибки)
state/chunks/*.txt              вытесненные фрагменты (доступны через laya_get_chunk)
state/circuit-breaker.json      состояние предохранителя (общее для процессов)
metrics/decisions-YYYY-MM-DD.jsonl  метрики решений
```

## Измеренные числа (эта машина, этот чекпоинт)

Замер на живой сборке (`node scripts/laya-eval.mjs`), чекпоинт
`multilingual-fp16-0b095e005a4c`, RTX 3060:

| Метрика | Значение |
|---|---|
| Детерминированные правила: FNR / FPR | **0 / 35** и **0 / 21** на наборе опасных/безопасных |
| Laya сама: `risk_class=high` на опасных | 7 / 35 (≈20% recall) |
| Laya сама: ложные «high» на безопасных | 0 / 21 |
| Режим `ask`: высокий риск → вопрос | 24 / 24 (100%) |
| Режим `ask`: безопасные → вопрос | 0 / 21 (FPR = 0) |
| Латентность Laya (end-to-end, 3 вопроса) | p50 ≈ 35 мс, p95 ≈ 49 мс, max ≈ 133 мс |
| Накладные хука на вызов инструмента | read-only команды — **~28 мс** (Go-лаунчер не запускает Node, −86%); Write/Edit и рискованные — ~320 мс (из них ~100 мс — старт Node, ~13 мс — HTTP, 35–50 мс — Laya). **stdout пуст: 0 токенов контекста** в режимах shadow/report/log |

Вывод, который эти числа доказывают: **Laya нельзя делать единственным барьером**
(она пропускает 4 из 5 опасных команд), но и не нужно: правила дают полноту,
Laya — ноль ложных срабатываний. Именно поэтому гейт устроен как «правила
эскалируют, Laya добавляет осторожности, а не наоборот».

Экономия вызовов Laya: политика `layaPolicy: "smart"` (по умолчанию) не
опрашивает модель на явно читающих командах (`ls`, `cat`, `git status`, `grep`,
`npm ls`…). По замеру это не теряет ничего: Laya ни разу не эскалировала без
сигнала правил, — зато снимает ~110 мс с каждого безобидного вызова. Любая
незнакомая команда (перенаправления, цепочки, свои скрипты), запись файлов и
любое сработавшее правило уходят к модели.

## Экономия контекста: A/B (2026-11-02)

Замер `node scripts/laya-context-economy.mjs` на этом же чекпоинте. Baseline —
старый путь: `rg` + полное чтение / прямой запуск проверки. В таблице — только
фактические байты; оценка токенов здесь не применяется.

| Задача | baseline | improved | шагов | контекст B → I | экономия байт |
|---|---:|---:|---:|---:|---:|
| поиск `activeModes` | 97 мс | 914 мс | 3 → 1 | 42 131 → 5 545 Б | 36 586 Б |
| чтение `gates.mjs` | 0.3 мс | 304 мс | 1 → 1 | 23 444 → 10 922 Б | 12 522 Б |
| `npm test` | 22.5 с | 20.7 с | 1 → 1 | 23 118 → 3 756 Б | 19 362 Б |

Восстановление: поиск — chunk содержит все 35 хитов; файл — chunk совпадает
побайтно; проверка — chunk содержит полный вывод. Латентность раздельно:
`/health` p50 **1.6 мс** (не скорость классификации), `/decide` p50 **26 мс**,
полный MCP-вызов `laya_search` **~649 мс** (включая холодный старт Node).

Хуки: permission-skip в Go-лаунчере — **120 мс** против **178 мс** того же
PreToolUse через Node; read-only при `smart` — **20 мс**. Улучшенный путь
поиска/чтения медленнее по wall-time, потому что переносит отбор в локальную
Laya; выигрыш — в контексте и в числе шагов. Это зафиксировано в отчёте, а не
выдано за ускорение.

## Агентный A/B/C: реальный usage (2026-11-02)

Один фикстур-проект, одна задача (найти и исправить баг, не менять `tests/`),
одинаковый prompt, модель `Kibborg_Flash_v5.7`, по 3 прогона:
A — raw (Laya-инструменты отключены), B — self-fetching при остановленной Laya,
C — self-fetching с Laya. Usage — от провайдера, без `bytes/2.8`.

**Семантика usage:** `inputTokens` провайдера **включает** `cacheReadTokens`
(проверено по `raw_usage_json`: `total = input + output`, `cache_read ≤ input`).
Поэтому «input» — это не «свежие» токены. Некешированный вход =
`input − cache_read`; стоимость по нему отдельно не считалась, потому что цена
кэш-чтения зависит от тарифов провайдера.

| Медиана | A raw | B без Laya | C с Laya |
|---|---:|---:|---:|
| input tokens (включая cache) | 359 085 | 264 062 | 239 544 |
| cache read | 336 281 | 236 410 | 211 777 |
| **некешированный input** (`input − cache`, медиана по прогонам) | **22 804** | **28 566** | **27 767** |
| total tokens | 361 230 | 265 806 | 241 389 |
| model requests | 16 | 10 | 9 |
| tool calls | 20 | 13 | 10 |
| wall, s | 119.1 | 89.9 | 91.1 |

Если вычитать медианы по отдельности, некешированный вход: 22,8 / 27,7 / 27,8
тыс.; вывод тот же. Все 9 прогонов успешны: `npm test` exit 0, скрытые
проверки пройдены, `tests/` не изменены, правился только
`src/pricing/discounts.mjs`.

- **A → B (детерминированный отбор):** total input −26.5%, model requests
  16→10, wall −24.5%; **некешированный input +25.3%**. Это не экономия
  «свежих» токенов и не расчёт стоимости — это меньше запросов и больше
  повторного использования контекста.
- **B → C (вклад Laya):** total input −9.3%, requests 10→9, tool calls 13→10,
  wall +1.3% (в шуме); некешированный input ≈−2.8% (в пределах разброса).
  Laya участвовала только в ранжировании `laya_search`; `read_relevant` на
  малых блоках шёл без Laya, `run_check` Laya не использует.
- **A → C:** total input −33.3%, wall −23.5%; некешированный input +21.8%.

Это n=3 на одной задаче: диапазоны B и C пересекаются, поэтому 9% — наблюдаемый
эффект, а не статистически доказанная константа. Основной выигрыш — меньше
запросов и tool calls, а не доказанное снижение стоимости токенов. Полный
отчёт — `experiments/agent-ab-2026-11-02.md`.

## Откат

1. Перед обновлением сохраните каталог плагина и
   `%USERPROFILE%\.zcode\cli\plugins\data\davinci-laya-decisions@*\config.json`.
2. Удалите/отключите плагин в ZCode Plugin Management и верните сохранённую копию.
3. Начните новую сессию ZCode: MCP-инструменты перечитываются при старте сессии.
   Laya при откате плагина не переустанавливается.

## Безопасность и границы

- Секреты маскируются **до** отправки в Laya (bearer, `sk-`/`ghp_`/AKIA, URL с
  учётными данными, `password=`, PEM-блоки, cookie, `.env`-строки), состояние
  усекается с маркером. Полное содержимое `.env`/ключей не отправляется.
- В метрики пишется `state_hash`, а не текст; полный prompt не сохраняется.
- Гейт не может `allow`/`deny`: только `ask` (после калибровки) или молчание.
- `Stop` не создаёт циклов: `stop_hook_active` + счётчик блокировок в ledger
  (по умолчанию 1 на сессию).
- Laya не даёт «гарантий безопасности»: это вероятностная модель ~322M.
  Её ответы — сигнал внимания, а не вердикт.
